\section{Method}
\label{sec:method}

\subsection{Rashomon set construction}
We binarize a curated subset of the UCI Adult dataset: the sensitive target $T = \texttt{sex}$ (single indicator column), background-knowledge attribute $A = \texttt{marital-status}$ (collapsed to 4 categories: Married, Never-married, Divorced, Widowed-Separated), background-knowledge attribute $B = \texttt{education}$ (collapsed to 5 categories: Below-HS, HS-grad, Some-college, Bachelors, Grad+), plus \texttt{age} and \texttt{hours-per-week} median-split indicators and a \texttt{capital-gain}$>0$ indicator -- 13 binary columns in total. The prediction label $Y$ is income ($>\$50$K vs.\ not).

This curated feature set is a deliberate scope reduction from the full $\sim$60-column binarization of Adult: with all columns included, TreeFARMS (Xin et al., 2022) only produced trees shallow enough (1--2 splits) at laptop-tractable regularization that none of them ever split on \texttt{sex}, making every background-knowledge condition identical by construction. Reducing the competing feature count lets $T$, $A$, and $B$ actually get selected as splits while keeping the exhaustive Rashomon-set search tractable.

For each of 50 repetitions (seeds), we sample $n = 100$ rows from Adult and build a Rashomon set with TreeFARMS using regularization $\lambda = 0.01$ (the same value Hsu et al., 2026, use for Adult) and Rashomon bound multiplier $0.1$ (all trees within $10\%$ of the optimal objective are kept). This produces substantially deeper, more expressive trees than an earlier pass of this experiment that used $\lambda=0.02$, bound multiplier $0.2$: average leaf depth rose from 1--3 splits to 5.7 splits, and in a 200-tree sample, 100\% of trees split on \texttt{sex} at least once (vs.\ 30\% before), with essentially all trees containing a leaf whose path jointly uses \texttt{sex} and $A$ or $B$ together. Since TreeFARMS's own search is single-threaded, the 50 repetitions are instead parallelized across seeds (one process per seed, 12-way) to fit within a practical wall-clock budget; each process pins its CP-SAT solves to a single thread to avoid oversubscribing the machine.

\subsection{Reconstruction attack}
We reimplement the constraint-programming reconstruction attack of Ferry et al.\ (2024, \emph{``Trained Random Forests Completely Reveal your Dataset''}, known as DRAFT), adapted to read TreeFARMS's native tree representation and to support fixing a subset of feature columns to their true value for every row (the attacker's background knowledge). The attack is solved with OR-Tools CP-SAT (no commercial solver license required): one boolean variable per (row, feature), one-hot-sum constraints per categorical attribute, and per-tree, per-leaf constraints forcing the solved table to reproduce the exact per-class training-example counts of the released trees. The label $Y$ is assumed known to the attacker in every condition, consistent with this literature: the released trees predict $Y$, so $Y$ is treated as public.

For a released ensemble of the first $m$ trees from the Rashomon set (TreeFARMS's enumeration order; no diversity-aware selection strategy is applied), we solve the attack under four background-knowledge conditions, holding the data sample and released trees fixed within a repetition:
\begin{itemize}
  \item \textbf{None}: neither $A$ nor $B$ is known.
  \item \textbf{A}: $A$ is known for every row; $B$ is not.
  \item \textbf{B}: $B$ is known for every row; $A$ is not.
  \item \textbf{A+B}: both $A$ and $B$ are known.
\end{itemize}
In every condition $T$ remains unknown. We sweep $m \in \{5, 10, 25, 50, 100\}$, with a 120-second solver timeout per (seed, $m$, condition) cell.

\subsection{Evaluation}
The solver has no notion of row identity beyond $Y$ (fixed per row index) and whichever columns are pinned as known; under partial background knowledge, rows sharing a label are otherwise interchangeable as far as the model's constraints are concerned. Before scoring $T$, we therefore match each reconstructed row to a true row via the Hungarian algorithm (within each $Y$-label group), using Hamming distance over every column \emph{except} $T$ as the matching cost -- excluding $T$ from the matching cost avoids letting the evaluator's own knowledge of the true values inflate $T$'s measured accuracy. Reconstruction error is the fraction of matched rows whose reconstructed $T$ disagrees with the truth.

We compare against two baselines: a uniform-random guess, and a holdout-marginal guess that samples $T$ from its empirical marginal estimated on a 2000-row holdout sample disjoint from the attacked 100 rows and never passed to the Rashomon-set construction or the attack.
